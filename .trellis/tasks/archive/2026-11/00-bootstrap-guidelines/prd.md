# Yaoguang 现状回填与开发规范初始化

## 目标

将已经交付的 Windows 下班熄屏工具的实际结构、行为、维护规则和验证边界沉淀到 Trellis，使后续开发可以依据当前实现开展；完成并关闭 `trellis init` 创建的默认任务。

## 范围

- 根据正式源码、构建脚本、README 和验收材料完善 `.trellis/spec/`。
- 用桌面应用规范替换未填写的通用后端模板，覆盖 Qt 界面与状态机、配置兼容、原生显示与输入、设备恢复、日志、质量和单文件 EXE 交付。
- 补充默认任务的真实需求、实现依据、验证记录和完成结论，并记录工作日志。
- 明确已实现、历史已验收、当前复核及尚未专项验证的区别。

## 约束

- 当前产品行为以四个正式 Python 模块及最终清理版验收记录为准。
- 不修改业务代码、用户配置、日志、交付 EXE 或既有验收记录。
- 不将优化建议、历史失败方案或已经移除的测试入口记为当前能力。
- 不为这次文档整理重新运行真实熄屏或暂停鼠标；检查应与本轮变更范围匹配。
- 用户本轮授权回填 Trellis 并关闭默认任务；不包含 Git 提交、远程推送或新功能开发。

## 验收标准

- [x] 规范准确描述当前 Windows Python + Qt 单文件工具，索引可被 Trellis 发现。
- [x] 关键行为有实际文件、符号或现有验收证据支撑，包含可操作的约束与代码示例。
- [x] 配置兼容、状态机、仅键盘唤醒与独立恢复的跨模块合同完整。
- [x] 不存在未填写模板、数据库/ORM 等不适用章节或 Trellis 上游项目的操作指令。
- [x] 质量规范区分静态检查、包核验、历史临时回归及真实 Windows 验收。
- [x] 默认任务具有真实执行记录；完成后状态为 `completed`，移入归档并记录工作日志。
- [x] 正式程序、个人数据和历史证据保持原样，改动仅限 Trellis 及相关说明。
