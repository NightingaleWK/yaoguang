- [x] 进入下班模式后，鼠标移动、桌面震动引起的微小位移均不点亮显示器。

- [x] 唤醒后无操作达到设定时间，再次进入同样的下班熄屏流程；不调用 Windows 锁屏。

## 当前验证发现

Windows 真实输入测试发现：低级鼠标钩子能够吞掉鼠标事件，但 Windows 仍会响应输入点亮显示器。因此，不能将“程序仍处于等待状态”当作“鼠标不会亮屏”的验收证据。失败记录保存在 `acceptance/2026-11-03-os-only-wake.json`。

已试验 DDC/CI：两台显示器写入待机/恢复指令均返回成功，但第二台不能读取电源状态，系统关闭显示信号后第一台的电源状态也不能作为可靠的在线读取证据。用户明确要求真正关闭显示信号，最终方案采用“临时暂停 Mouse 类设备 + Windows 熄屏指令”，不交付黑色遮罩，也不依赖 DDC/CI 方案。

仅键盘唤醒版本的 12 项回归检查、6 项 EXE 原生检查已通过，用户已确认两台屏幕熄屏和鼠标恢复正常。用户随后明确修正：计时到期应再次进入下班模式关闭信号，不能主动锁屏。

自动再次熄屏修正的 16 项回归检查、7 项最终 EXE 原生检查均通过，包含重复循环、操作重置计时、取消倒计时、10 秒旧配置迁移及自动进入失败后的恢复。已直接驱动最终 EXE 的真实 Qt 界面完成“手动熄屏 → 按键唤醒 → 10 秒计时结束后再次熄屏 → 再次按键恢复”的闭环验证。

用户确认功能正常后，已移除发行程序内的验收模块与测试命令入口，并清理旧版实现、临时测试目录和约 535 MB 的旧构建产物。当前只保留 4 个正式运行模块，清理后 16 项回归检查再次通过。

当前交付以 [清理版验收记录](验收记录-2026-11-03.md)、`acceptance/2026-11-03-cleanup.json`、`acceptance/2026-11-03-build.json` 为准。历史功能验证、界面截图与早期试验记录统一保存在 `history/`，不包含在 EXE 中。

已核对的 Windows 官方接口说明：

- [LowLevelMouseProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc)：说明输入钩子的作用与线程要求。
- [BlockInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-blockinput)：会同时拦截键盘和鼠标，不适合作为普通权限下的仅键盘唤醒方案。
- [SetVCPFeature](https://learn.microsoft.com/en-us/windows/win32/api/lowlevelmonitorconfigurationapi/nf-lowlevelmonitorconfigurationapi-setvcpfeature)：硬件显示器控制依赖显示器的 DDC/CI 支持，需要实际验证恢复能力。
- [CM_Disable_DevNode](https://learn.microsoft.com/en-us/windows/win32/api/cfgmgr32/nf-cfgmgr32-cm_disable_devnode)：默认暂停不会跨重启持久保存；本轮不设置持久标志。
- [CM_Enable_DevNode](https://learn.microsoft.com/en-us/windows/win32/api/cfgmgr32/nf-cfgmgr32-cm_enable_devnode)：恢复本轮暂停的鼠标设备。
